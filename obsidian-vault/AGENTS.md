# ChatGPT × Obsidian 记忆协议

本仓库是当前 ChatGPT/Codex 的持久记忆库。默认用中文，结论先行，简洁直给。

## 每次任务开始

1. 先读 `00-System/USER.md`。
2. 再读 `98-AI-Context/CURRENT.md`，了解当前目标、状态和下一步。
3. 需要长期经验时读 `97-AI-Memory/README.md`，再按链接读取决策、最佳实践或深层知识。
4. 与活跃项目相关时，读 `06-Projects/<项目>.md`；需要历史细节时再进入对应的 `30-Projects/<项目>.md`。
5. 需要追溯原始记录时，才搜索 `10-Inbox/`、`20-Daily/` 和 `90-Archive/`；不要把整个库一次性灌入上下文。

## 写入规则

- 只有用户明确要求“记住、记录、保存到记忆”时，才新增持久记忆。
- 用户偏好、沟通风格、审批边界 → `00-System/USER.md`
- 已验证的跨项目经验、决策、工作流和最佳实践 → `97-AI-Memory/`
- 当前任务状态、阻塞项和下一步 → `98-AI-Context/CURRENT.md`
- 活跃项目目标、状态和下一步 → `06-Projects/<项目>.md`
- 精炼核心事实和记忆路由 → `00-System/MEMORY.md`
- 某个项目专属事实和决策 → `30-Projects/<项目>.md`
- 跨项目的研究知识 → `50-Domains/<领域>.md`
- 尚未验证、待整理或一次性材料 → `10-Inbox/YYYY-MM-DD-主题.md`
- 当天工作流水和临时上下文 → `20-Daily/YYYY-MM-DD.md`
- 可重复执行且做过至少两次的方法 → `40-Playbooks/<方法>.md`

## 自动更新触发

任务完成后，仅当出现以下任一结果时才更新记忆：

- 形成经过验证、未来可复用的经验
- 做出会影响后续工作的明确决策
- 建立或修改稳定工作流
- 推进活跃项目的状态、阻塞或下一步
- 发现比现有做法更可靠的最佳实践

不要保存聊天记录、逐轮对话、临时情绪、一次性命令输出或未经验证的猜测。

## 安全与质量

- 禁止保存密码、API key、token、Cookie、TOTP、二维码、银行卡完整信息和私有后端地址。
- 事实必须标注来源和最后确认日期；不确定内容标记 `status: unverified`。
- 新事实写入前先搜索去重；发生冲突时保留双方证据并请用户裁决，不静默覆盖。
- `USER.md` 建议小于 2,000 字符，`MEMORY.md` 建议小于 3,500 字符；超限时把细节下沉到项目或 playbook。
- 删除、覆盖、外发、发布前必须获得用户确认。编辑前尽量备份，编辑后必须回读或运行健康检查。

## 对用户的交付

- 中文解释。
- 如果准备提交 Git，提交前先列出验证命令并执行。
- 发布或外发前必须获得确认。


## 统一入口与读取顺序

- 统一入口：`Home.md`。不得使用或重新生成 the legacy snapshot index file。
- 标准读取顺序：
  1. `00-System/USER.md`
  2. `98-AI-Context/CURRENT.md`
  3. `00-System/MEMORY.md`
  4. 最少的相关项目或长期记忆页面
- GitHub 共享仓库只保存公开安全副本；Vault 是本机唯一记忆读写入口。
